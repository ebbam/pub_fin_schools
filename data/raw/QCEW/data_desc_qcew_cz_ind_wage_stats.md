## QCEW County- and CZ-level Wage Statistics
<!-- Data description for data cleaning procedure in qcew_cz_ind_wage_stats.R -->
<!-- This cleans the county and commuting zone level industry-specific wage statistics (time-varying) -->

We obtain time-varying county-level wage data from the Bureau of Labor Statistics' Quarterly Census of Employment and Wages (QCEW) for the years 1998-2022. The data cleaning process involves several key steps. First, we exclude observations flagged as non-disclosed (Disclosure Code = "N"), remove Puerto Rico and other U.S. territories, and filter to county-level geographic units while correcting for historical FIPS code changes. We retain only observations with non-zero average weekly wages and focus on industry aggregation level 74 ([Aggregation Level Codes](https://www.bls.gov/cew/classifications/aggregation/agg-level-titles.htm)), which represent a 2-digit NAICS sectoral classification. 

Two challenges impeded a straight-forward cleaning process. First, 2-digit NAICS sector-level employment and wage information (aggregation level = 74) is not consistently reported across all counties. In this case, this is likely not due to disclosure restrictions or limited industry presence, as more specific NAICS code numbers are often reported, despite missing higher-level industrial aggregates (i.e., a particular county might report employment and wage statistics for a 3-digit industrial classification but not the higher-level 2-digit classification). Second, QCEW only reports sector-county-level statistics by ownership sector ([Ownership Level Codes](https://www.bls.gov/cew/classifications/ownerships/sic-ownership-titles.htm)) requires a reconciling of wage data reported for public versus private sector employment. We reconcile both challenges in the following way. For counties where 2-digit NAICS sector-level data (aggregation level = 74) is available, we aggregate across ownership codes by calculating the maximum wage, simple mean wage, and employment-weighted mean wage for each county-industry pair. For counties lacking 2-digit sector-level data, we instead use the most aggregated industry classification available (minimum aggregation level code) and aggregate these observations to the NAICS 2-digit sector level, applying the same wage calculations. This approach allows us to maintain comprehensive county coverage while using the most detailed industry classification available in each jurisdiction. We verify that the two groups contain non-overlapping county-industry pairs before combining them into a single dataset.

We then aggregate these county-level statistics to the commuting-zone level.
